# پروفایل افزونه وردپرس

## اطلاعات لازم

فقط موارد مؤثر بر سازگاری و استقرار ثبت شوند:

- نسخه اصلی WordPress و PHP
- Single Site یا Multisite در صورت اثرگذاری
- قالب یا افزونه‌های کلیدیِ مرتبط
- روش نصب و غیرفعال‌سازی
- وجود داده، Migration یا Uninstall حساس

Patch دقیق PHP، فهرست کامل افزونه‌ها، CDN، Cache و جزئیات هاست فقط وقتی بررسی شوند که قابلیت واقعاً به آن‌ها وابسته باشد یا خطای سازگاری مشاهده شود.

## کنترل‌های فنی

- استفاده از WordPress API به‌جای SQL مستقیم، مگر با دلیل روشن
- Capability و Nonce برای عملیات مدیریتی تغییردهنده
- Sanitization ورودی و Escaping خروجی
- Prefix مناسب
- رفتار روشن Activation، Deactivation و Uninstall متناسب با داده افزونه
- ZIP قابل نصب برای افزونه قابل‌انتشار
- Smoke Test در محیطی نزدیک به مقصد

## حالت سبک

برای افزونه کوچک و بدون Schema، پرداخت، داده حساس یا سرویس خارجی:

1. پیاده‌سازی
2. تست محلی یا Harness
3. ساخت ZIP
4. نصب آزمایشی
5. نصب روی سایت با امکان غیرفعال‌سازی سریع

Backup کامل، تمرین Restore، بازبینی مستقل، بررسی تمام نسخه‌های دیتابیس و تأییدهای چندمرحله‌ای اجباری نیستند. اگر افزونه فقط Option محدود و قابل‌حذف دارد، غیرفعال‌سازی یا حذف استاندارد می‌تواند راه بازگشت کافی باشد.

## حالت استاندارد یا بحرانی

در صورت Migration، داده مهم، پرداخت، احراز هویت، تغییر گسترده Frontend یا وابستگی به زیرساخت:

- Backup متناسب
- Staging یا پنجره انتشار کنترل‌شده
- آزمون Upgrade و Rollback
- بررسی Cache و امنیت مرتبط
- تصمیم انسانی پیش از اقدام پرخطر Production

## اصل سازگاری محیط

Codex باید نسخه هدف را با محیط واقعی هماهنگ کند. اگر سایت PHP قدیمی‌تری دارد و کد بدون خطر روی آن قابل پشتیبانی است، کاهش حداقل نسخه و اجرای تست ترجیح دارد؛ ارتقای زیرساخت نباید برای یک قابلیت ساده بدون ضرورت فنی تحمیل شود.
