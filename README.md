# MASEF — کارخانه نرم‌افزارسازی عامل‌محور مناهل

**نسخه:** 0.2.0  
**هدف:** تحویل سریع و قابل‌اعتماد نرم‌افزار با اجرای فنی کامل توسط Codex و حداقل توقف برای تأیید انسانی.

## مدل عملیاتی

```text
مالک محصول هدف را تعیین می‌کند → Codex تصمیم فنی می‌گیرد و اجرا می‌کند → تست خودکار نتیجه را می‌سنجد → فقط اقدام‌های واقعاً پرخطر متوقف می‌شوند
```

- مالک محصول: مسئله، اولویت، نتیجه مورد انتظار و محدودیت‌های کسب‌وکار را مشخص می‌کند.
- Codex: تحلیل فنی، طراحی، کدنویسی، تست، رفع خطا، مستندسازی، Git و آماده‌سازی انتشار را مستقل انجام می‌دهد.
- تأیید انسانی فقط برای تصمیم‌های کسب‌وکاری حل‌نشده، دسترسی محرمانه، اقدام برگشت‌ناپذیر، حذف داده مهم یا استقرار پرخطر لازم است.
- چارچوب هیچ دروازه یا تأییدیه دینی ندارد. محتوای تخصصی مانند هر داده دامنه‌ای با منبع، تست و کنترل یکپارچگی مدیریت می‌شود.

## سه حالت اجرا

### سبک

برای افزونه کوچک، اسکریپت، ابزار شخصی و تغییر برگشت‌پذیر:

- Codex از نیاز تا Artifact را یکپارچه انجام می‌دهد.
- برنامه رسمی، Threat Model، بازبینی مستقل و Evidence Pack اجباری نیستند.
- تست مرتبط و گزارش کوتاه کافی است.
- فقط پیش از تغییر Production یا داده واقعی، در صورت وجود خطر معنادار، توقف می‌شود.

### استاندارد

برای قابلیت چندفایلی، فرم، API، کاربر، داده یا اتصال خارجی:

- برنامه کوتاه، تست، CI و راه بازگشت لازم است.
- Codex بدون تأیید مرحله‌به‌مرحله پیش می‌رود.
- یک نقطه تصمیم پیش از استقرار اصلی یا مهاجرت داده کافی است.

### بحرانی

برای پرداخت، اطلاعات حساس، احراز هویت، حذف گسترده، مهاجرت سخت، سلامت، حقوق یا دسترسی زیرساختی مهم:

- کنترل‌های امنیتی و شواهد کامل‌تر اجرا می‌شود.
- تأیید انسانی فقط در نقاط پرخطر و مشخص گرفته می‌شود.
- توقف‌های تکراری یا تأییدهای صوری ممنوع است.

## شروع سریع

```bash
python scripts/bootstrap_project.py \
  --name "نام پروژه" \
  --slug "project-slug" \
  --profile wordpress-plugin \
  --risk light \
  --output ../project-slug
```

سپس:

```bash
cd ../project-slug
python scripts/validate_framework.py
```

فایل `START-HERE.md` مسیر مناسب همان سطح خطر را مشخص می‌کند.

## پروفایل‌های فنی

- `generic`
- `wordpress-plugin`
- `webapp`
- `api-service`

پروفایل‌ها فقط کنترل‌های فنی مرتبط را اضافه می‌کنند و نباید فرایند را بی‌دلیل سنگین کنند.

## اصل قطعی

Codex باید بر پایه اصول فنی، منطق، تست و شواهد تصمیم بگیرد. پرسشی که پاسخ آن از کد، مستندات، محیط یا آزمون قابل استخراج است نباید به مالک محصول منتقل شود. هدف چارچوب، تحویل نرم‌افزار است؛ مستندسازی و تأیید فقط ابزار کاهش خطر هستند، نه خودِ محصول.
