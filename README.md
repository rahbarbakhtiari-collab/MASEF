# MASEF — کارخانه نرم‌افزارسازی عامل‌محور

**نسخه:** 0.3.0  
**تمرکز فعلی:** کارخانه خودمختار ساخت افزونه WordPress  
**هدف:** تبدیل یک ایده کوتاه به محصول آزموده، مستند و قابل‌نصب با حداقل دخالت فنی مالک محصول.

## مدل عملیاتی

```text
ایده مالک محصول
    ↓
تحلیل و تکمیل محصول توسط ChatGPT
    ↓
یک خلاصه محصول و یک تأیید انسانی
    ↓
اجرای مستقل Codex از طراحی تا ZIP و Release
    ↓
تحویل بسته آماده نصب
```

- مالک محصول هدف، محدودیت کسب‌وکار و نتیجه مورد انتظار را تعیین می‌کند.
- ChatGPT نقش مدیر محصول و تحلیل‌گر را دارد و ایده را به خلاصه محصول قابل‌آزمون تبدیل می‌کند.
- Codex رهبر فنی و مجری است و معماری، کدنویسی، تست، رفع خطا، مستندسازی، GitHub و بسته‌بندی را مستقل انجام می‌دهد.
- مالک محصول نباید مدیر فنی یا پیام‌رسان میان عامل‌ها باشد.
- تأیید انسانی پس از خلاصه محصول فقط برای مانع واقعاً انسانی، هزینه، Secret، اقدام برگشت‌ناپذیر، Production پرخطر یا پذیرش خطر مهم لازم است.

## اصل اصلی MASEF 0.3

> مراحل ثابت، عمق شناور، اجرای خودمختار، تأیید انسانی استثنایی.

چرخه مهندسی در همه پروژه‌ها حفظ می‌شود:

1. مسئله و نتیجه
2. نیازمندی‌ها
3. معیارهای پذیرش
4. طراحی فنی
5. پیاده‌سازی
6. آزمون
7. بازبینی
8. بسته‌بندی
9. آمادگی استقرار

سطح `light`، `standard` یا `critical` فقط عمق مستندات، امنیت، آزمون و شواهد را تغییر می‌دهد؛ هیچ‌کدام از مراحل اصلی را حذف نمی‌کند.

## سیاست ثابت افزونه‌های WordPress

پروفایل `wordpress-plugin` دارای سیاست الزامی و یکپارچه است:

- حداقل PHP `8.1`
- حداقل WordPress `7.2`
- رابط اصلی فارسی و RTL، ولی کاملاً ترجمه‌پذیر
- پنل ساده، تنظیم‌پذیر و دارای پیش‌فرض‌های کاربردی
- حفظ داده هنگام غیرفعال‌سازی و حذف پیش‌فرض
- حذف کامل داده فقط با گزینه صریح مدیر
- بدون Telemetry و ردیابی پیش‌فرض
- وابستگی خارجی فقط با توجیه واقعی؛ بدون CDN و Secret در مخزن
- امنیت، Upgrade، Migration، Changelog و نگهداری آینده الزامی
- آمادگی کامل برای WordPress.org از نسخه نخست
- نویسنده: **رهبر بختیاری**
- مجوز: `GPL-2.0-or-later`
- مخزن افزونه ابتدا خصوصی و در زمان آمادگی انتشار عمومی می‌شود

سند کامل: `docs/00-governance/WORDPRESS-PLUGIN-FACTORY-POLICY.md`

## سه سطح اجرا

### سبک

برای افزونه محدود، برگشت‌پذیر و بدون داده حساس. همه مراحل مهندسی انجام می‌شوند، اما اسناد و آزمون‌ها فشرده و متناسب‌اند.

### استاندارد

برای افزونه چندماژولی، داده معمولی، فرم، API، اتصال خارجی یا اثر واقعی بر کاربران. برنامه کوتاه، CI، آزمون واقعی و راه بازگشت لازم است.

### بحرانی

برای پرداخت، اطلاعات حساس، احراز هویت، مهاجرت دشوار، حذف گسترده یا پیامد جدی. امنیت، شواهد، آزمون سوءاستفاده و کنترل استقرار عمیق‌تر می‌شوند.

## شروع سریع

```bash
python scripts/bootstrap_project.py \
  --name "نام افزونه" \
  --slug "plugin-slug" \
  --profile wordpress-plugin \
  --risk standard \
  --output ../plugin-slug
```

سپس:

```bash
cd ../plugin-slug
python scripts/validate_framework.py
```

فایل `START-HERE.md` جریان کار را مشخص می‌کند و `SELECTED-PROFILES.md` سیاست پروفایل انتخاب‌شده را در پروژه ثبت می‌کند.

## محیط آزمون WordPress

ترتیب پیش‌فرض:

1. LocalWP موجود
2. تشخیص و تعمیر معقول LocalWP
3. Docker و محیط WordPress مستقل
4. آزمون جایگزین قوی همراه با ثبت محدودیت، فقط وقتی اجرای واقعی واقعاً ناممکن باشد

نصب نهایی Production و تغییر داده واقعی Production بر عهده مالک محصول است؛ Codex بسته نصب، شواهد آزمون و راه بازگشت را آماده می‌کند.

## خروجی ثابت افزونه

- ZIP نصب‌شدنی
- مخزن سالم، Tag و Release

- `readme.txt` انگلیسی مناسب WordPress.org

## اصل قطعی

Codex باید با کد، مستندات، پژوهش، آزمایش و شواهد تصمیم فنی بگیرد. پرسشی که پاسخ آن از ابزارها یا محیط قابل استخراج است نباید به مالک محصول منتقل شود. هدف چارچوب، تحویل محصول نگهداری‌پذیر است؛ فرایند و مستندات ابزار کنترل کیفیت‌اند، نه جایگزین محصول.
