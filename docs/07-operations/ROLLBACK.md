# راه بازگشت متناسب با خطر

## اصل

راه بازگشت باید با پیامد واقعی شکست متناسب باشد. هدف بازگرداندن سرویس به وضعیت قابل‌استفاده است، نه اجرای تشریفات یکسان برای همه پروژه‌ها.

## Triggerهای عمومی

- خطای بحرانی یا HTTP 500
- شکست مسیر اصلی کاربر
- ازبین‌رفتن یا خراب‌شدن داده
- ناسازگاری جدی با محیط
- افزایش غیرعادی خطا
- مشکل امنیتی مهم

## سطح سبک

برای تغییر کوچک و بدون Migration:

1. غیرفعال‌سازی قابلیت یا افزونه
2. حذف یا Revert نسخه جدید
3. Smoke Test
4. ثبت علت کوتاه

اگر داده مهمی تغییر نکرده است، Restore پایگاه داده یا تمرین بازیابی لازم نیست.

## سطح استاندارد

1. توقف ادامه استقرار
2. ثبت نسخه و وضعیت فعلی
3. بازگرداندن Artifact یا Commit قبلی
4. بازگرداندن داده فقط در صورت تأثیر Migration
5. Smoke و بررسی لاگ
6. ثبت Incident مختصر

## سطح بحرانی

1. فعال‌کردن برنامه Incident
2. محدودکردن ترافیک یا عملیات جدید در صورت نیاز
3. Restore یا Down Migration آزمایش‌شده
4. بررسی یکپارچگی داده
5. Smoke و مشاهده‌پذیری کامل
6. ثبت زمان، تصمیم‌ها و نتیجه
