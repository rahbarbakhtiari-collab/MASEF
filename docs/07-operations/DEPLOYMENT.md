# راهنمای استقرار متناسب با خطر

## اصل

استقرار باید ساده‌ترین روش امن و برگشت‌پذیر متناسب با اثر تغییر باشد. پروژه سبک نباید به فرایند انتشار سامانه بحرانی مجبور شود.

## سطح سبک

نمونه: افزونه کوچک بدون Migration یا داده حساس.

پیش‌شرط‌ها:

- تست مرتبط موفق است.
- Artifact یا فایل نصب مشخص است.
- راه بازگشت ساده مانند غیرفعال‌سازی، حذف یا Revert وجود دارد.
- در صورت اثر روی Production، مالک محصول یک‌بار اجازه نصب می‌دهد.

مراحل معمول:

1. ثبت نسخه یا Commit
2. نصب
3. فعال‌سازی
4. Smoke Test مسیر اصلی
5. بررسی خطای آشکار
6. ادامه یا بازگشت ساده

Backup کامل، Maintenance، Staging مستقل، تمرین Restore و Evidence Pack اجباری نیستند مگر داده یا شرایط سایت آن را لازم کند.

## سطح استاندارد

پیش‌شرط‌ها:

- تست و CI موفق
- Backup متناسب با داده در معرض خطر
- راه بازگشت روشن
- پنجره استقرار در صورت اثر روی کاربران

مراحل:

1. ثبت نسخه و Artifact
2. Backup لازم
3. استقرار کنترل‌شده
4. Migration در صورت وجود
5. Smoke و بررسی لاگ
6. اعلام نتیجه یا Rollback

## سطح بحرانی

برای پرداخت، داده حساس، مهاجرت دشوار یا زیرساخت مهم:

- محیط آزمایشی نزدیک به Production
- Backup قابل‌بازیابی
- Rollback آزمایش‌شده
- مسئول پاسخ و پنجره تغییر
- مشاهده‌پذیری و کنترل پس از انتشار
- تصمیم انسانی پیش از اقدام Production

## سازگاری محیط

- فقط اطلاعاتی بررسی شوند که واقعاً بر قابلیت اثر دارند.
- نامشخص‌بودن Patch دقیق نسخه، Handler یا Extension زمانی مسدودکننده است که شواهدی از وابستگی یا ناسازگاری وجود داشته باشد.
- برای تغییر ساده، تست واقعی روی محیط مقصد از استعلام‌های طولانی و فرضی ارزشمندتر است.
