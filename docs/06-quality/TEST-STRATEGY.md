# راهبرد آزمون متناسب با خطر

## اصل

کمترین مجموعه آزمونی را انتخاب کنید که خطاهای مهم همان تغییر را کشف کند. تعداد تست بیشتر به‌تنهایی نشانه کیفیت نیست.

## سطح سبک

- Unit یا Harness برای منطق اصلی
- Smoke یا Integration برای مسیر واقعی
- آزمون دستی فقط برای ظاهر یا رفتار غیرقابل‌خودکارسازی

E2E کامل، ماتریس گسترده نسخه‌ها و تست مستقل امنیتی فقط در صورت وابستگی واقعی لازم‌اند.

## سطح استاندارد

1. Unit برای منطق دامنه
2. Integration برای پایگاه داده یا سرویس‌ها
3. E2E برای مسیرهای مهم کاربر
4. Security Test برای سطح حمله مرتبط

## سطح بحرانی

- مسیرهای موفق و شکست
- هم‌زمانی و یکپارچگی داده
- امنیت و مجوز
- بازیابی و Rollback
- سازگاری محیطی مهم
- مشاهده‌پذیری پس از انتشار

## قواعد

- Bug fix در صورت ارزش عملی باید تست بازگشتی داشته باشد.
- تست نباید برای سبزشدن مصنوعی تضعیف شود.
- زمان، شبکه و داده تصادفی در صورت اثرگذاری کنترل شوند.
- داده Production خام وارد تست نشود.
- مسیر خطای مهم آزموده شود.
- Codex نوع و عمق تست را بر اساس خطر انتخاب می‌کند و برای هر تست از مالک محصول اجازه نمی‌گیرد.
