# چک‌لیست بازبینی مستقل

> فقط برای تغییر بحرانی، تغییر استاندارد پرخطر یا درخواست صریح استفاده شود. پروژه سبک به بازبینی مستقل اجباری نیاز ندارد.

## انطباق با نتیجه

- [ ] نتیجه مورد انتظار واقعاً تحویل شده است.
- [ ] تغییر خارج از محدوده با پیامد منفی اضافه نشده است.
- [ ] معیارهای مهم پذیرش پوشش داده شده‌اند.

## درستی

- [ ] خطاهای مرزی و مسیر شکست مرتبط بررسی شده‌اند.
- [ ] تست‌ها نقص‌های مهم را تشخیص می‌دهند.
- [ ] پیچیدگی یا Mock مصنوعی کیفیت را پنهان نکرده است.

## امنیت و داده

- [ ] ورودی، مجوز و خروجی در سطح حمله مرتبط امن‌اند.
- [ ] Secret یا داده حساس نشت نکرده است.
- [ ] عملیات مخرب و Migration کنترل متناسب دارند.

## نگهداری و بازگشت

- [ ] راه‌حل بی‌دلیل پیچیده نیست.
- [ ] مستندات لازم و راه بازگشت متناسب‌اند.

## نتیجه

- Verdict: Approve | Approve with notes | Request changes | Block
- فقط Blocker و High باید تحویل را متوقف کنند.
- Medium و Low توسط عامل سازنده اصلاح یا به‌عنوان خطر باقی‌مانده ثبت می‌شوند و نیازمند تأیید انسانی عمومی نیستند.
