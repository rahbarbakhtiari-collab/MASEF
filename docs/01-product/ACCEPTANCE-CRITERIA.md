# معیارهای پذیرش

معیارها باید نتیجه قابل مشاهده یا قابل آزمون را بیان کنند. برای پروژه سبک، یک فهرست کوتاه کافی است و قالب Given/When/Then اجباری نیست.

## قالب اختیاری دقیق

### AC-001 — عنوان

**Given / با فرض اینکه:**  
**When / هنگامی که:**  
**Then / آنگاه:**

- نوع تست: Unit | Integration | E2E | Manual
- فرمان یا روش آزمون:
- نتیجه مورد انتظار:
- وضعیت: Draft | Automated | Passed | Failed

## قواعد

- Codex نوع تست و روش اثبات را بر اساس رفتار انتخاب می‌کند.
- هر معیار نیازمند تأیید انسانی نیست؛ تست خودکار یا مشاهده مستقیم ترجیح دارد.
- بازبینی دستی فقط برای تجربه بصری، تصمیم کسب‌وکاری یا رفتاری که خودکارسازی آن ارزش ندارد استفاده شود.
- تعداد معیارها باید متناسب با پیچیدگی باشد و برای پوشش صوری افزایش نیابد.

## نمونه هم‌زمانی

### AC-EXAMPLE — جلوگیری از رزرو تکراری

**با فرض اینکه** یک سهم آزاد است و دو کاربر هم‌زمان آن را انتخاب می‌کنند،  
**هنگامی که** هر دو درخواست به سرور برسد،  
**آنگاه** دقیقاً یک رزرو ثبت شود، درخواست دوم پاسخ روشن دریافت کند و هیچ رکورد تکراری ایجاد نشود.
