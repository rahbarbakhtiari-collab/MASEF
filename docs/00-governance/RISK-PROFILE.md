## تعیین حالت اجرا

### سبک

وقتی همه شرایط زیر برقرارند:

- تغییر کوچک یا محدود است؛
- داده حساس، پرداخت یا مهاجرت مهم ندارد؛
- بازگشت با حذف، غیرفعال‌سازی یا Revert ساده ممکن است؛
- شکست، اثر محدود و قابل‌تحمل دارد.

### استاندارد

وقتی یکی یا چند مورد زیر وجود دارد:

- تغییر چندفایلی یا چندماژولی؛
- داده معمولی، فرم، API یا اتصال خارجی؛
- اثر واقعی روی کاربران ولی بدون پیامد شدید؛
- نیاز به استقرار کنترل‌شده یا Backup معمولی.

### بحرانی

وقتی یکی از موارد زیر وجود دارد:

- پرداخت یا اطلاعات حساس؛
- احراز هویت و مجوزهای مهم؛
- حذف گسترده یا مهاجرت دشوار داده؛
- سلامت، حقوق یا پیامد سازمانی شدید؛
- تغییر زیرساختی یا بازگشت نامطمئن؛
- اثر وسیع و فوری بر Production.

## اصل کاهش اصطکاک

- موضوعات محتوایی یا تخصصی به‌خودی‌خود سطح خطر را بالا نمی‌برند؛ فقط پیامد واقعی خطا ملاک است.
- وجود WordPress، افزونه یا سایت Production به‌تنهایی پروژه را بحرانی نمی‌کند.
- نسخه Patch دقیق محیط فقط وقتی مسدودکننده است که سازگاری واقعاً به همان Patch وابسته باشد.
- Codex باید سطح خطر را پیشنهاد دهد و کار را ادامه دهد؛ فقط اختلافی که پذیرش ریسک انسانی می‌خواهد مطرح شود.
