# سیاست امنیت

## اصول پایه

- کمترین سطح دسترسی لازم
- اسرار خارج از مخزن و خروجی‌ها
- اعتبارسنجی ورودی و Escape خروجی متناسب با Context
- بررسی مجوز و CSRF Protection برای عملیات تغییردهنده
- وابستگی‌های محدود و قابل‌ردیابی
- شکست امن و پیام خطای غیرحساس
- تست امنیتی متناسب با خطر واقعی

## اختیار عادی Codex

Codex بدون تأیید جداگانه می‌تواند:

- کد و اسناد غیرحساس را بخواند و تغییر دهد؛
- تست محلی و CI را اجرا کند؛
- از شبکه برای مستندات رسمی، مخازن عمومی و ابزارهای از قبل مجاز استفاده کند؛
- وابستگی توسعه‌ای کم‌خطر نصب کند؛
- وابستگی تولیدی رایج را پس از بررسی فنی اضافه کند، مشروط به نداشتن هزینه، Secret یا اثر Production؛
- Schema را در محیط توسعه یا آزمایشی تغییر دهد و Migration/تست/بازگشت تهیه کند؛
- روی شاخه کاری Commit، Push و Draft PR ایجاد کند.

## موارد نیازمند تصمیم انسانی

فقط این موارد متوقف شوند:

- ورود به حساب یا دریافت Secret از مالک؛
- ایجاد هزینه یا قرارداد سرویس خارجی؛
- تغییر مستقیم Production با خطر معنادار؛
- حذف یا تغییر برگشت‌ناپذیر داده مهم؛
- تضعیف کنترل امنیتی؛
- پذیرش خطر امنیتی باقی‌مانده مهم.

## ممنوع

- چاپ، انتقال یا Commit کردن Secret
- دورزدن احراز هویت یا مجوز
- حذف انبوه داده بدون راه بازگشت و تصمیم انسانی
- خاموش‌کردن کنترل امنیتی برای عبور تست
- استفاده از `--dangerously-bypass-approvals-and-sandbox` خارج از محیط ایزوله و صریحاً مجاز

## اصل تناسب

وجود شبکه، وابستگی یا محیط مشترک به‌تنهایی دلیل توقف نیست. عامل باید اثر واقعی، برگشت‌پذیری و دسترسی موردنیاز را ارزیابی کند و فقط در صورت خطر معنادار تصمیم را به انسان منتقل کند.
